Project profile: SHUD-Harness（dsh 内核，ADR-0004）

Living artifact maintained by `subagent-workflow` Phase 0.0/0.5. Rewritten 2026-10-20 at the Phase 4 reset; the Zero-era profile is in tag `archive/zero-v0.8.3`.

Entry surfaces:
- `packages/dsh-shud-*/` TypeScript plugin packages (pnpm workspace, `tsc` → `lib/`, vitest). Present: `dsh-shud-core` (8 object Zod schemas, policy-gate-core, role-tool-map), `dsh-shud-raw-guard`, `dsh-shud-jobs` (durable registry and file-level startup recovery), `dsh-shud-tools`, `dsh-shud-records` (record APIs, not a mounted plugin), `dsh-shud-policy-gate`, and `dsh-shud-presets` (global role restriction and exported coordinator/worker prompts).
- `profile/shud/` dsh bundle (`package.json` + `cordis.patch.yml`): model routing, outbound channel switches, workspace-package plugin mounts, exact coordinator/worker preset subtrees and Web default coordinator. Raw-guard precedes policy-gate; role-restrict is global and config-free. Host subagent registry/provider stay enabled once globally. Persona reads exported prompt assets through Loader `!!js`; workspace instructions remain agent-instructions' responsibility. The product is `dsh --profile shud`; there is no app of our own.
- `scripts/schema/` (Zod → `docs/generated/{schema,json-schema}`), `scripts/docs/` (link checker); `skills/`, `scripts/` (R/bash), `templates/` to come with M3.
- Contract sources: `docs/adr/implemented/0004-dsh-kernel.md`, `docs/04_IMPLEMENTATION/Phased_Plan.md` (M1–M6, sole truth for gates), `docs/03_SPEC/*`, `docs/00_INDEX/CANONICAL_CONTRACTS.md`, `openspec/changes/*`.
- Host: dsh checkout `../deepseek-harness` pinned `dsh-v0.2.1-rc.2` — read-only runtime host, never modified, never imported from loop internals. Plugin types come from published devDependencies `@deepseek-ai/dsh-tools@0.2.1-rc.2` and `@deepseek-ai/cordis@4.0.5`, not the checkout. Spike evidence: `../dsh-spike/runs/1.1–1.5`.
- Read-only submodules: `SHUD/`, `rSHUD/`, `AutoSHUD/`.

Contracts:
- Local workflow evidence: [ADR-0009](../docs/adr/proposed/0009-local-evidence-boundary.md) governs all writers, including issue/PR review and design/stage-pipeline. Root `.workplans/` is local-only: `issue-<number>/`, `pr-<number>/`, and `<change-name>/` share one Git/Prettier boundary. Never place sources/deliverables there, force-add evidence, or rewrite consumed oracle bytes for formatting; publish review-relevant commands, outcomes and limits in the PR summary rather than relying on local files.
- Plugins touch only documented seams: `tools/pre-execute` waterfall (`allow|deny|cancel|ask`), `ctx.tools.guard()`, `ctx.approval` (fail-closed), `ctx.jobs` (`JobRegistry`), `ctx.sandbox`, `ctx.storage`, agent presets. A needed-but-missing seam is a reported deviation, not a fork.
- 8 core objects (TaskCard, StackLock, DataProvenance, RunJob, RunRecord, AnalysisPlan, EvidenceReport, ChangeRequest); field source = `docs/03_SPEC/Minimal_Schemas.md`, code = `packages/dsh-shud-core/src/schemas/`, projection = `docs/generated/` (must not drift).
- Mounted collection tool (#315): `shud_collect` accepts exactly one core-branded `job_id`/`run_id`, using the same closed-schema/unknown-key adapter as `shud_run`. One registry-owned operation resolves active-before-completed indexes independently of caller cwd and returns the canonical immutable RunRecord; no tool-side filesystem discovery or retries. Nonterminal/in-flight rejection includes validated current status and nullable current registration; queued D7 diagnostic reads remain read-only and drain before unlock. Collection failures preserve the controlled generation reason even when ledger publication fails; terminal full-schema validation remains inside the journaled collection attempt.
- StackLock.llm = `base_url` + `request_alias` + `response_model` (K4); the strict core schema and fingerprint align with these fields, and response_model is recorded but excluded from the fingerprint, never auto-invalidating a lock. Branded StackId, minimal runtime/harness and repository dirty paths/truncation are aligned in #430; `captureStackLock` persistence and submission integration remain future M3 work.
- Governance invariants (K12): physics/default-parameter/benchmark-baseline changes need PI approval via `ask`; single-basin metric gain ≠ model improvement; calibration ≠ structural validation; raw data deletion forbidden or PI-gated, `data/raw` lives outside the workspace root (Seatbelt read-only).
- Scope rule (K13): no spike may start unless it ends in one user-visible step of the first task (ccw run → RunRecord → EvidenceReport).
- Outbound: only `session-log-deepseek` disabled (K9); every dsh upgrade re-audits new outbound rows.
- Deployment: default `rawDirs: ["data/raw"]` is for development/probes. The user overrides it with `- id: shud-raw-guard` + `config: { rawDirs: ["<absolute data_root/raw path outside the workspace>", ...] }` in `$DSH_HOME/profiles/shud/cordis.patch.yml`. `profile:install` requires an absolute executable regular-file `SHUD_BIN` and owns the unique `shud-jobs` patch item, including capture configuration. Headless additionally owns only the `disabled` flags of unique `preset-coordinator` and `preset-worker` items: both true, no registry/default setting, other preset properties preserved. All three targets are validated in memory before one atomic publication; precheck rejects unsafe/duplicate/shared targets without patch or manifest writes. Web leaves user preset-disable overrides alone. Raw overrides and unrelated bytes are preserved; identical repeats retain bytes/mode/inode/mtime. State-directory ownership and atomic serialized indexes are implemented by `dsh-shud-jobs` at apply time, requiring Darwin `lockf` or Linux `flock` plus `ps` (`procps` in Linux slim environments). Linux submitted recovery also requires readable `/proc/<pid>/stat`, `/proc/uptime` and validated `getconf CLK_TCK`; see [Runtime Lifecycle](../instructions/agents/shared.md#runtime-lifecycle) for configuration ownership, capture sources and runtime prerequisites.
- Running, cancellation, settlement and collection API: `ShudJobRegistry.submitShud(request, producer)` copies inputs, persists submission/index state and registers through a transient unscoped controller, then atomically persists a validated `running` RunJob with genuine wrapper identity before retaining its completion receipt and clearing in-flight membership. The required `producer(prepared, handle, pumpPollMs)` returns `ShudExecution`; exported `startDetachedShud(prepared, hooks, pumpPollMs)` requires `ShudLifecycle` (JobHooks, idempotent synchronous/asynchronous `settle`, and required synchronous `detach(detail)` sharing the actual producer-owned done) and the Cordis-resolved parent interval consumed by the registry. Local submissions and startup R3/R5 takeovers share the internal minimal group/completion capability; adopted registrations own no native child and fabricate no started/waitForExit/abort methods. Genuine local cancellation still awaits native-child reaping before producer completion. Public `kill(id, caller, reason)` remains synchronous: parent access/terminal preflight precedes durable cancellation intent, then a one-shot mark authorizes SIGTERM through the locally spawned or validated recovered group capability. Managed ownership requires an actual current-instance submission/takeover association, not reason text or arbitrary kind labels; non-managed registrations retain parent behavior. Reentrant registered-event kill before current-id publication refuses with identity MISMATCH and no intent/signal; postcommit takeover kill uses the same path. The existing cadence escalates at the core 10-second deadline from the first request, without extending it on repeats or adding timers. Group quiescence gates durable cancellation settlement even when the leader exits before a resistant descendant; exit evidence still wins. Cancellation, poll terminal writes and collector status projections use one fresh, non-yielding RunJob publication boundary so older snapshots cannot clobber intent. One dispatcher serves timer ticks and public `pollOnce()`, joining in-flight entries for manual ticks while independent entries progress. Normal settlement persists the terminal state before producer completion, whose retries do not rewrite durable terminal evidence. Later ticks collect terminal entries; backend `collectShud(RunId | JobRecordId): Promise<RunRecord>` shares the same per-entry queue and collector, completing any pending receipt first. Immutable RunRecord publication commits the result before the `collected` projection; projection repair does not regenerate it or consume generation attempts. A durable error ledger gates automatic retries at 10-second intervals, up to 3 attempts; direct collection bypasses the interval/cap but not corrupt-ledger rejection. Successful retries preserve historical error bytes/mtime. Settlement and collection leave active indexes intact. A composite effect closes admissions, drains accepted startup reconciliation/takeover cleanup, settlement/collection (including queued direct calls) and submission/rollback work, then releases state ownership without awaiting natural detached-process completion; closed-instance managed classification survives concurrent parent cancellation delivery. Wake delivery and normal completed-index migration (#313), and tool entrypoints remain unimplemented. Runtime Lifecycle above documents evidence rules and collector commit boundaries; API probes do not constitute full host/Web recovery or PI acceptance.
- Host teardown: successful nonterminal cancellation persistence mirrors the original timestamp into local requestedAt before parent kill; parent rejection revokes only the one-shot mark, not the durable intent/mirror. For both local and adopted registrations, unmarked managed cancel synchronously detaches the same real registration as failed with controlled host-exiting detail. Plain teardown sends no signal; intent-bearing teardown resends owned-group TERM before completion, reports sanitized signal/inspection errors, and still detaches in finally. It does not forward the original rollback cancel, read/write RunJob/indexes, collect, notify, send KILL, wait for the process or reset the deadline. Accepted R8/normal work still drains before lock release. Owner-Agent release leaves unowned SHUD running for normal settlement/collection, including adopted registrations. Native STOP→TERM controls distinguish Linux's surviving T-state leader/R8 original-deadline quiescence from Darwin's exited leader/R7 cancelled with a live resistant descendant: the latter is the explicit #343 limit, not Darwin R8 evidence. See [Park/Resume §§8–9](../docs/03_SPEC/Park_Resume_Design.md#8-幂等与锁).
- Startup reconciliation: Cordis `[Service.init]` awaits R1–R12 reconciliation and R3/R5 takeover attempts before normal cadence and SHUD submit/manual-poll/collect admission. The original #310 slice was registration-free; #312 now uses R3's freshly promoted running record or R5's validated running identity to recover group ownership and create one real unowned `kind: shud` registration through the existing transient unscoped controller, retaining the run-id-plus-optional-label convention and original stdout. It clears stale current id first, installs managed hooks/identity inside the producer callback, then publishes the new current id/appended history and completion receipt without yielding. No SHUD respawn occurs; repeated ticks do not register again, while a later instance appends one fresh id. Contained registration/new-id publication failures retain the cleared null id and old history, emit sanitized diagnostics, detach/drain/remove any created parent entry, and release managed classification last without physical abort or deleting run/index evidence. Cleanup failures retain incomplete classification and report; failure to clear an unwritable stale id remains an error, never a fabricated null write. After contained registration failures, file-only polling/collection continues without registration retries; other unfinished reconciliation errors retain the existing retry behavior. Recovered R8 cancellation remains registration-free, may hold readiness for the remaining original grace, and must drain before ownership release. Existing startup locking and composite drain are unchanged. No wake delivery is introduced; pending notify is unchanged, while validated delivered/unreachable entries receive completed-first R12 index repair. R9 reuses the canonical collector's valid committed-record priority over retry history. Linux R3 freshness uses native proc start ticks/uptime, validated cached `getconf CLK_TCK` and bracketed realtime bounds; lstart remains the unchanged identity token for locks/RunJob/R5/R7. Invalid or uncertain observations fail closed. See [Park/Resume §9](../docs/03_SPEC/Park_Resume_Design.md#9-服务重启恢复) and [design D11 / startup execution boundaries](changes/archive/2026-10-27-m2-run-chain/design.md) for recovery behavior, PID/orphan-group limits (#343), and original-instance observation-window semantics for `wall_seconds` (#344): missing/recovered observations yield null for new records; valid committed records remain immutable, without retroactive certification or solver-runtime precision/bound claims.

Risk axes:
- dsh pre-stable API drift (seam renames, config schema changes) across `chore(dsh-upgrade)` issues; `--patch` ordering (must precede app args).
- rc.2 tool integration: `defineTool` has an open parameter root; strict tool contracts require both a closed model-visible schema and explicit unknown-key rejection at execution. Runtime `@deepseek-ai/dsh-tools` imports need the full pinned peer closure under `autoInstallPeers: false`; type-only imports do not prove runtime importability.
- PI approval versus filesystem access (#511): SHUD retains read-only/workspace-write/danger-full-access sandbox modes, all paired with ask, plus global ask even under DSH_PERMISSION_MODE=danger-full-access. Restored durable never overrides remain untouched until explicit public-preset reselection (old sessions may show custom); user patch ownership remains unchanged. Host never auto-rejection can say “user rejected” before any answerer dispatch: asked/decided alone is not UI/PI evidence. Headless/no-answerer stays fail closed; automated full-access proof does not close M3 PI acceptance. The focused real-service test-only seam is documented in [proposed ADR-0012](../docs/adr/proposed/0012-full-access-approval-test-seam.md).
- Job durability: in-memory `jobs-local` dies with the process (SIGTERM kills child without `job/settled`, SIGKILL orphans it, restart → `unknown job`); M2's durable backend must survive both.
- Raw-data byte protection relies on `<data_root>/raw` being outside the workspace root; any plugin that widens the sandbox or resolves symlinks into it breaks the invariant.
- Schema drift between `Minimal_Schemas.md`, Zod code, generated docs and issue text.
- Secrets: `DMXAPI_KEY` only via env (`apiKeyEnv`); never in RunRecord, reports, session logs committed as fixtures, or git.
- Scientific governance boundaries: agent never states scientific conclusions; report wording rules are tested constants, not prompts alone.
- Ported >1000-line files (`policy-gate-core.ts` + test) are guard-excluded; new code must not hide behind that exclusion.
