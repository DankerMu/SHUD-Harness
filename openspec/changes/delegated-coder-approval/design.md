# Design

## Context

See proposal.md and #614's PI decision. The pinned host writes delegation `never` during unpublished setup, then publishes awaited `agent/created`, then starts the child turn. Setup records are not re-emitted as live `session/event`. Public projections materialize those records; `agent/created` source distinguishes startup from resume. Web transport is child-addressable by source inspection, not yet demonstrated under ask.

## Goals / Non-Goals

Governing invariant: only a provably fresh, unseeded, live-owned coder with an authorized live parent may receive this one-time SHUD policy initialization; initialization never grants an operation or overrides explicit/restored never.
Must preserve: rc.2 host/read-only checkout; parent policy and captured sandbox; all existing tools, role masks and approval outcomes; restored policy bytes; M3 root approval and worker behavior; #547's exact two engineering approvals and #549's independent PI operation.
Non-goals: generic permission inheritance/synchronization, changing policy when roles switch or plugins reload, automatic grants, timers/retries, host migration, new persisted event families, or replay/solver implementation.

## Decisions

1. Add a named global `shud-coder-approval` plugin exported from the existing presets package, not hidden policy side effects inside role-restrict. Keep preset subtrees and headless disabled flags unchanged; the new global plugin is inert for unknown/root/non-coder callers.
2. Register one small host-only projection through `ctx.sessionProjections.register/stateOf`. Track child-owned policy count, latest value/source/seq, and whether a turn has begun; retain only necessary state. The inherited-prefix boundary comes from projection initialization. No new `eventAt`, `snapshotEvents`, `ownEvents`, aliases, disk-log scans or live-event-only reconstruction.
3. At `agent/created`, synchronously check: source startup; exact live child registry identity; unseeded subagent metadata and consistent depth/parent id; exact live parent ownership via `agents.isOwnedBy`; current role coder; no prior child turn; exactly one child-owned policy event, `never` with source delegation; actual child service still reports never. Resolve the parent's current override or configured policy through its public service, requiring explicit ask and no missing/unknown value. Missing capability/provenance means no policy write. Never infer ask from an absent service/config or merely from a creation header.
4. This is new PI-authorized initialization at publication, not inheritance of a delegation-time approval snapshot. Check the live parent at the final non-yielding write boundary; a parent that became never while creation awaited stays closed. Do not claim to know the parent's unrecorded pre-await approval value. No later automatic synchronization with parent switches.
5. Use the documented exported `setApprovalPolicy` initialization setter with an exact-file, named-only import exception recorded in ADR-0013. Do not use `setPolicy`, which fabricates a user-attributed switch notice, nor write source delegation on SHUD's own event. Queue a `createUserMessage` notice via public Agent.inject with source kind `shud-coder-approval`, child policy sequence and parent identity/policy observation. It states initialization, not approval or a PI click. If post-write notice setup fails, restore never only if this write still owns the current policy, then fail creation; preserve original and rollback errors, never retry or continue with an unreported success.
6. Make creation handling once-per-Agent and effect-bound. Repeated callbacks cannot append a second initialization; resume/clear/compact, seeded/forked or already-executed sessions cannot opt in. Later explicit policy writes win, including never; preset changes do not re-enable. Persisted ask is retained like any other existing policy, not re-granted on restore. Disposal removes listeners/projection and does not rewrite user policy history.
7. PI explicitly authorized the policy-neutral context revision in [comment 6649912974](https://github.com/DankerMu/SHUD-Harness/issues/614#issuecomment-6649912974). The host's registered `approval:policy` is the sole owner of current ask/never wording. SHUD replaces only the delegated coder's contradictory delegation entry with a distinctly named, policy-independent explanation of fixed delegation/sandbox boundaries and actual answerer/allowed-once requirements. It declares neither current policy nor current role. Do not register a second dynamic policy provider or retain original-text state: after assembly is accepted, host refresh deliberately preserves an entry whose provider was removed; replacement providers cannot recover an old instance's WeakMap. A static truthful explanation remains valid through policy/role changes, disposal and remount, while the host policy context refreshes its current value. Preserve all unrelated contexts and non-coder assembly behavior; keep the post-await effect-ownership check. No cancellation, leaked registrations, retained-assembly cache or host modification. This replaces the earlier literal never-text/dynamic-provider constraint with explicit PI authorization, not an approval-policy exception.
8. Reuse the real-service harness from full-access-approval.test.ts by extraction into one exact-path approval test harness; migrate its existing caller without behavior changes. Extend its narrow named constructor imports there, not across tests or production. Preserve mock-based tests for their existing purposes but do not use them as this issue's policy-before-answerer proof. No new host dependency tree; actual delegation is covered separately in the real Web host.

## Sibling Surfaces and Evidence

Siblings: parent and child policy services/projections; initial and resumed agent lifecycle; role restriction/current preset; permission presets/sandbox; runtime-context assembly; ToolRuntime pre-execute and actual change_submit writes; Web owner waterfall transport; profile install/smoke; default lint/import guardrails; existing full-access and M4 prompt tests.
Required evidence: fresh owned coder + parent ask + held real answerer remains undecided/no CR write until allowed-once; rejected/unavailable/cancelled and parent/explicit/restored never preserve CR/task/patch bytes. Include setup-window projection reconstruction, bad/missing ownership, seeded session, prior turn, duplicate announcement, changed parent before publication, and failure cleanup. Reuse the same accepted assembly through a held preparation interval, plugin disposal/remount and policy changes in both directions; actual `refreshContext` must retain truthful policy-neutral delegation/sandbox guidance and the current host policy without empty or stale policy/role claims. Do not substitute a fresh reassembly for the retained-assembly case. Actual Web child `change_submit` on explicitly constructed inert records must bind parent/catalog, policy provenance, request callId, asked/decided ids, admitted context and result for allowed/rejected outcomes; compare CR/task/patch bytes and distinguish the fixture from real scientific changes.
Evidence limits: true-service tests may reproduce the host's durable child seed and use an identity/registry double, but cannot claim actual manager creation. The real Web probe supplies that separate fact. HTTP/WS proves owner answerer transport, not browser rendering, a human click, scientific correctness or #549 acceptance.

## Risks / Trade-offs

- Unknown or ambiguous provenance → no opt-in; do not guess or fall back to policy writes.
- Global ask broadens which operations can request a decision in an authorized coder, not what they may execute → actual answerers remain mandatory; #547 must reject extra asks rather than auto-grant them.
- Child approval cards are associated with the child view, not guaranteed visible in the root sidebar → document navigation/transport limits; prove human workflow only at #549.
- Named host imports are currently prohibited outside existing exceptions → explicit ADR and exact-path positive/negative guardrail evidence, never general allowlisting or threshold relaxation.

## Delivery and Containment

First review/strict-validate this fixture. Parent runs a tracer RED through real services, implementer adds the smallest behavior, parent runs GREEN; iterate for uncertain boundaries. Then full check, profile smoke, guardrails, real Web allowed/rejected smoke and three-seat review precede exact-head CI/merge. Failure leaves #547 blocked. Removing the new plugin stops future automatic initialization but does not silently rewrite already persisted policies; operator policy changes use existing public controls. No automatic migration or host edit is part of rollback.
