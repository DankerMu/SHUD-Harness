Findings:
- P1 / process lifecycle escape / A bash invocation must not leave active descendants that can mutate workspace or audit state after the tool reaches a terminal result / Evidence: `Bun.spawn(... detached: true)` starts the wrapper as a new process group, containment then tracks only sampled descendants by PPID (`packages/core/src/tools/raw-data-sandbox.ts:1072`, `packages/core/src/tools/raw-data-sandbox.ts:1535`, `packages/core/src/tools/raw-data-sandbox.ts:1648`), while preflight only rejects a small regex set such as `setsid|setpgrp|daemonize|start_new_session` (`packages/core/src/tools/raw-data-sandbox.ts:3283`) / Scenario or repro: `node -e 'require("child_process").spawn(process.execPath,["-e","setTimeout(()=>require(\"fs\").renameSync(\"workspace/tasks\",\"workspace/tasks.moved\"),200)"],{detached:true,stdio:"ignore"}).unref()'` contains no `&`, `setsid`, or `setpgrp`, can exit immediately, and the detached child can run after the wrapper has appended an allowed audit row / Consequence: terminal `tool.completed` state and audit evidence can be stale while a live descendant mutates allowed workspace paths or audit ancestors / Fix direction: enforce runtime containment for daemonized children, or fail closed on programmatic detach/process-creation forms instead of relying on shell-token regex and PPID sampling / Required verification: add a regression with a detached child that delays a workspace/audit-ancestor mutation; assert the tool fails or the child is killed before return and no late mutation appears after a sleep / Sibling surfaces: timeout, abort, allowed command completion, audit ancestor moves, future background task execution / Blocks merge: yes.
- P1 / evidence-state false success / Any attempted `data/raw/**` mutation denied by the OS sandbox must surface as a failed tool result plus `tool.failed` audit evidence, not `allowed` / Evidence: post-exec denial classification returns true only when the command analysis has a known raw target (`packages/core/src/tools/raw-data-sandbox.ts:3398`), and target recognition is limited to literals, path constructors, joined paths, or specific fragmented signals (`packages/core/src/tools/raw-data-sandbox.ts:2643`) / Scenario or repro: `python3 -c 'try: open(chr(100)+"ata/raw/hidden.txt","w").write("x")\nexcept PermissionError: pass'` attempts a protected raw write, the sandbox prevents bytes, the interpreter swallows the error, and the static recognizer has no known raw target / Consequence: audit can record `tool.completed`/`allowed` even though the command attempted to mutate protected evidence input / Fix direction: do not require recognized raw target syntax when an interpreter payload both uses write-capable APIs and suppresses errors, or add reliable syscall-denial telemetry before returning success / Required verification: add obfuscated-path swallowed-exception tests for Python and Node; assert failed `raw_data_write_denied`, `tool.failed`, no raw mutation, and matching audit/profile identity / Sibling surfaces: interpreter payloads, stderr/exit normalization, advisory-disabled mode, WS event payload conversion / Blocks merge: yes.
- P2 / compatibility false denial / Advisory/static analysis must not block legal raw reads or workspace writes merely because the command is hard to analyze / Evidence: when analysis exceeds budget, `analyzeRawDataCommand()` forces `hasHiddenEvidenceRisk: true` (`packages/core/src/tools/raw-data-sandbox.ts:644`), and `evaluateSuppressedSandboxFailureGuard()` pre-denies before spawning (`packages/core/src/tools/raw-data-sandbox.ts:605`); the added test explicitly denies a large workspace-only write (`packages/core/src/tools/raw-data-sandbox.test.ts:2434`) / Scenario or repro: a long generated command such as `printf ok > workspace/out.txt 2>/dev/null; true # <140k filler>` never touches `data/raw`, but is returned as `raw_data_write_denied` and does not execute / Consequence: unchanged legal bash workflows can be rejected by the pre-exec scanner, reintroducing static authority over commands the OS sandbox should safely allow / Fix direction: make budget exhaustion fail open unless there is an independently recognized protected target, or return a distinct “command too large for advisory evidence” error that is explicitly specified as a compatibility policy / Required verification: add over-budget legal raw-read and workspace-write tests that succeed under the sandbox, plus over-budget known raw-write tests that still fail safely / Sibling surfaces: generated R/Python shell commands, long pipelines, advisory-disabled mode, registry outer raw rule / Blocks merge: no, if explicitly accepted as a bounded-command policy; otherwise yes for the stated compatibility contract.
