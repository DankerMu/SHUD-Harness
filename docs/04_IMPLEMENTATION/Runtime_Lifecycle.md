# Runtime Lifecycle 细则

> 本文从根指令 `instructions/agents/shared.md` 的 Runtime Lifecycle 一节原文迁出（2026-11-06），是这些规则的唯一归宿，强制效力不变。启动命令、安全恢复禁止动作、Web/headless 启动以及部署覆写与证据规则仍留在根指令 [Runtime Lifecycle](../../AGENTS.md#runtime-lifecycle)。

`profile:install` 要求 `SHUD_BIN` 是绝对路径、可执行普通文件；缺失或无效时在创建/修改 profile 前失败，不回退默认路径。安装器先以 `web` 模板创建 `shud`，再 `link:` 安装本仓库 bundle：禁用旧 `jobs` 行，并插入 `shud-jobs`（不是按 id 改 name）。安装器整体拥有用户 patch 的唯一 `shud-jobs` 项：`shudBin`、`stateDir: $DSH_HOME/profiles/<name>/shud-jobs`、自身仓库根派生的 `stackRepos.{SHUD,rSHUD,AutoSHUD}`、bundle dsh peer 的 `hostVersion`、bundle provider/model 行的 `llm.{base_url,request_alias}`，以及可选 `SUNDIALS_ROOT` 对应的 `sundialsRoot`。三仓库目录须存在（可为空，提交才检查 Git）；设置的 SUNDIALS_ROOT 须为已存在绝对目录，未设置则删去该键；这些检查均先于建档。apply 严格校验捕获键及父类键并集，不做采集。M2 项原位补齐，raw 覆写与其它字节保持不变，相同配置重装不改文件；不读取或序列化密钥。

Web 默认 preset 为 `coordinator`（`preset-coordinator.config.order: 1`），另有 `worker`、`coder`、`reviewer`；新增 coder/reviewer 不设 order、不改变默认项。四者按序挂 persona、agent-instructions（maxBytes 65536）、time-context；coordinator/worker 随后挂 tool-jobs，coder 挂 tool-fs、tool-bash（read/edit/bash，无 jobs），reviewer 挂 tool-fs、tool-jobs（只读文件，实际 jobs 面仅 job_output/job_list，无 job_kill）。两处 tool-fs 均显式 read true、write/readImage false，coder edit true、reviewer edit false。coordinator 再按序挂 tool-subagent、tool-subagent-coder、tool-subagent-reviewer，toolName/agentPreset 分别为 subagent/worker、subagent_coder/coder、subagent_reviewer/reviewer，均为 provider spawn、modelSelectionSettings false；其它三角色不挂委派工具。子树不沿用 stock 工具、不挂 restrict。宿主 subagent 注册表及 spawn provider 各一次启用，不覆写 maxDepth。persona 的 Loader `!!js` 从 `@shud-harness/dsh-shud-presets/prompts/{coordinator,worker,coder,reviewer}.md` 四个导出资产读取 prompt，不嵌入副本或机器路径；agent-instructions 仍负责工作区指令发现。安装器与 smoke 的 YAML 元数据读取不执行 `!!js`。

`shud-role-restrict` 是无固定 role 配置的全局行；raw-guard 仍紧邻且先于 policy-gate，jobs 替换与 tools 顺序不变。restrict 在 agent/created 与 committed agent-preset/selected 后按当前会话投影绑定 Agent 的 inherited 工具面；不读取创建 header 判断切换后的角色。restrict 的 inherited allow 与 policy-gate 的 inherited/local 判定共用 core role-tool map：coordinator 的 inherited 九项不变，为 task_create、report_generate、report_validate、report_submit、report_decide、shud_collect、job_output、job_list、job_kill，local 三项 subagent、subagent_coder、subagent_reviewer 不放进 inherited allow；worker 五项为 shud_run、shud_collect、job_output、job_list、job_kill；coder 六项为 bash、read、edit、change_create、change_submit、shud_build；reviewer 五项为 read、verification_run、shud_collect、job_output、job_list；后三者 local 均为空。unknown 不绑定角色限制；独立 policy-gate 仍按当前角色做执行时检查。raw-guard 对会话工作区的 tasks/、stacks/、provenance/、reports/、runs/、changes/、patches/、verifications/、builds/ 九个治理根拒绝 edit/write 及 bash 可识别的写入，须走专用领域工具；raw deny/ask 优先，bash 识别仅为启发式，不保证任意 shell 命令安全。配置 dump 只证明装配与表达式；真实工具面证据取 canonical session log 的 request/header.data.header.tools，prompt 资产文本证据取 system/message.data.message.content，不把 header 当作 prompt 载体或把 smoke 当作 PI 功能验收。

重绑先成功安装新 mask 再释放旧 mask；同角色 committed 事件不叠加，失败保留原限制并明确报告，unknown 切换及 Agent/插件释放只撤销本插件的绑定，不触碰其它来源的限制。不订阅早于投影提交的 tools/change 来判断角色。

headless 安装是用户 patch 所有权的唯一扩展：除整项拥有的 shud-jobs 外，只拥有唯一 preset-coordinator/preset-worker/preset-coder/preset-reviewer 的四个 disabled 字段并写 true，保留四项其它属性及目标范围外字节。五个目标全部在内存验证后只做一次原子发布；precheck 使用同一路径而不写入，任一重复项、共享 anchor 或不安全/无效输入使整次更新失败，不先发布 jobs 或第一个 preset。保留注释、raw 覆写、CRLF、flow/缩进/document-end、mode；相同配置不改 bytes/inode/mtime。Web 重装不清除用户刻意的 preset disabled 覆写，不负责同名 profile 的模板转换。

`shud-jobs` 在 apply 时取得 `stateDir` 的排他所有权，维护 `active.json`/`completed.json`：索引修改在实例内串行执行，以临时文件 + rename 原子替换，先写 completed 再移出 active。内部 `stateDir/.lock-guard` 是永久协调 inode，不可删除或改名；`lock` 保存 `{pid, pid_started_at}`。唯一组合生命周期 effect 开始释放时同步停止轮询定时器、关闭轮询、collect、托管 SHUD kill 与提交准入，并行等待已接受的启动对账、结算/收集步骤（含排队的直接 collect、异步完成回调）、通知 flush/失败记账/标记发布与提交/回滚事务结束，再关闭索引修改准入、等待索引写入完成，最后在持有内核 guard 时尝试删除锁元数据，无论删除成败都尝试关闭描述符；成功时元数据删除且内核锁释放，索引保留。父类 disposer 并发运行，状态解锁不能提前清除仍可能收到父类 cancel 的托管登记分类；正常完成/成功回滚会释放对应关联，关闭实例的剩余关联随实例回收。停止不等待脱离包装进程自然结束，但必须排空已接受的恢复取消；不以提交在途集合清空为条件。第二个持有者被拒绝；已发布持有者的诊断包含 stateDir 与 pid。

锁释放采用诊断＋运维恢复策略（#335）：每个实例只有一次自动释放尝试、零自动重试，不新增 retry API、定时器、owner nonce 或 live-self 自动接管。失败包含 `stateDir`、`lock` 路径、失败操作与错误码，原始错误由 cause/aggregate 保留；初始化与清理同时失败时，初始化错误仍是主因。只有描述符关闭成功才能报告 kernel guard released；关闭失败报告状态未知。unlink 非 ENOENT 失败只说明删除失败、可能残留，ENOENT 则说明元数据缺失，仍是失败而非成功；不额外读盘猜测结果。既有外层生命周期负责报告一次，不在底层重复记录；`close()` 缓存同一 promise/rejection，权限恢复后再次调用也不会重试删除或重复报告。guard 空闲但元数据匹配存活的本进程时，apply 仍拒绝，并标明“疑似自身释放残留、需运维核实”；真实 guard 争用和外来存活持有者仍按原规则拒绝。

运行前提：Darwin 的 `/usr/bin/lockf` 或 Linux 的 `/usr/bin/flock`，以及用于进程身份检查的 `ps`（Linux slim 环境需安装 `procps`）；Linux submitted 恢复还需可读 `/proc/<pid>/stat`、`/proc/uptime` 与有效 `getconf CLK_TCK`。检查固定 locale/时区；不支持的平台、缺失工具或无法确定的进程检查均明确失败，不作不安全回退。锁与 RunJob 身份仍使用秒级 `ps lstart`（RunJob 转为 ISO UTC）；R3 新鲜度另用可比较的出生时间证据，不改锁或 R5/R7 身份判据。时钟不确定性与 PID/组代次限制见 [重启恢复](../03_SPEC/Park_Resume_Design.md#9-服务重启恢复)。

注册表已提供 `submitShud(request, producer)`：请求显式携带会话 cwd、输入路径、project、owner_session 与模型元数据；可选品牌 `task_id` 在文件系统操作前校验，缺省为 null。必需的 `producer(prepared, handle, pumpPollMs)` 返回 `ShudExecution`；可调用已导出的 `startDetachedShud(prepared, hooks, pumpPollMs)`，其中 hooks 是调用方显式提供的 `ShudLifecycle` 登记生命周期依赖，没有默认空实现。注册表消费 Cordis 按父类 schema 已解析的 `pumpPollMs`，并将同一值供给提交、执行组件与轮询，不另查或新增默认值。提交按物理路径解析 cwd/输入根（保留符号链接与 `..` 的实际遍历语义）；已存在的 runs 根先以 lstat 拒绝链接/非目录，再以 native realpath 解析实际拼写（包括文件系统大小写别名），用于包含关系检查和运行目录记录；尚不存在的根仍从物理 cwd 派生。完整复制普通文件/目录，只在副本改写可选的 END；拒绝内部链接/特殊文件、符号链接运行目录，以及运行根或 stateDir 位于输入树内的布局。随后规范 captureStackLock 与 generateProvenance 先持久化 lock/副本清单，await 后复核运行目录所有权；首次 created 同时写入 task_id 与非空 stack_id/data_id，collect 原样继承，M2 null-id schema/恢复不变。持久化顺序为 created → 活动索引 → submitted（dsh id 为 null）→ 瞬时全局控制器下的无 owner 登记 → 写回 dsh id/历史 → 等待真实启动身份 → 原子写 running、pid、pid_started_at、started_at，随后登记本地完成回执，最后清除进程内在途标记并返回校验过的 `running` RunJob。真实登记回调在调用 producer 前关联 dsh id 与运行，再附加实际执行能力；启动失败时直到进程、登记与自有文件/索引回滚成功，才同步释放该关联并清除 D7，失败回滚仍拒绝 kill。stdout.log 经父类输出控制提供增量内容，控制器不常驻。

`shud_run` 的既有 raw-guard 在执行前按 canonical/最近存在祖先检查三个写入根 `runs`、`stacks`、`provenance`；任一根等于或位于配置 raw 内即 `raw-immutable` deny，先于输入读取审批且不受参数缺失/错误或 rawDirs 顺序影响。jobs 输入预检另保护原输入：采集根按 native realpath 的实际拼写（含大小写别名）比较，等于或位于原输入树内即在副作用前拒绝；仅输入位于采集根子目录不构成该重叠，独立记录/路径校验仍适用。

实际执行使用 detached `/bin/sh` 包装进程，以位置参数 `"$@"` 传递命令，stdout/stderr 追加到运行目录日志，宿主关闭自身日志描述符并 unref 子进程。包装进程须先成功原子发布 `wrapper.pid` 才能启动 SHUD；自然结束后原子发布 `exit_code`，包括非零退出码。包装进程可在宿主 SIGKILL 后继续运行；`exit_code` 是求解器退出证据，子进程事件不直接结算 RunJob。

`ShudExecution` 包含 `hooks`、真实身份的 `started` promise、受控组能力 `isGroupActive()` / `signalGroup("SIGTERM" | "SIGKILL")` / `waitForExit()` 与回滚专用 `abort()`；显式取消和回滚共用所有权检查。`ShudLifecycle` 在 `JobHooks` 上要求两个幂等完成入口：正常终态的 `settle(JobOutcome): void | Promise<void>` 与登记级退出的同步 `detach(detail): void`。两者释放实际登记资源并完成同一个 producer-owned `done`，不另造完成 promise；detach 以 failed 结束登记，不改 durable 运行结果。原 supplied `cancel` 仅供提交回滚，不代替正常结算或宿主 teardown。回滚先证明执行组已不能继续 I/O 并完成本地子进程回收，再取消/等待登记资源、移除父类登记与自有索引/目录，并移除本地完成回执；`hooks.done` 本身不是进程终止证据。尚未回收的原生子进程仍占有其 pid，即使启动时的身份查询失败也可据此回滚，不重复依赖失败的启动戳查询。原生未知非 Z 状态仍按可能 I/O 处理，无法确定的组检查拒绝继续；权限拒绝仅在重新检查明确静止后才可继续，否则保留运行路径与错误原因。已回收的原包装进程 PID 再次出现时拒绝向该组发信号，但不声称能识别替代组的 leader 也已退出的全部历史代次；非 SHUD 父类生命周期不改动。
提交回滚另删除本次成功返回且普通文件/父目录身份仍匹配的 provenance；链接/外来替换或清理失败保持 fail-closed，不释放预留/D7，不删除任何新建/复用 StackLock 或其它 provenance。采集及其回滚继续由既有提交 pending 集合 drain 后才解锁。

本地提交与启动接管共用内部最小 `ShudControl` / `ShudCompletion`：受控组检查/信号能力，以及共用实际登记 done 的 settle/detach。R3/R5 接管从已验证身份恢复组控制，不拥有新原生子进程，不伪造 `started`、`waitForExit` 或 `abort`；这些能力仍属于实际本地 `ShudExecution`。本地取消完成仍先等待真正的 native-child waiter，再完成 producer；接管没有本地子进程回收步骤，但取消仍受组静止约束，登记清理仍等待真实父类输出泵。

注册表在 Cordis `[Service.init]` 等待 R1–R12 启动对账及 R3/R5 接管尝试完成后才启动正常 cadence 并就绪；此前 `submitShud()`、`pollOnce()`、`collectShud()`（含 root/non-strict 访问）明确拒绝。启动对账绝不等待 `resolveAgent`，即使可选会话服务已经可用；冷会话恢复可能等待自身插件激活。恢复取消可使就绪等待首次取消请求的剩余 10 秒宽限期，不从重启重计。对账与正常轮询共用逐条目排他队列，不同条目独立推进；未完成的对账错误保留证据并由既有 cadence 重试，不阻塞其它条目。已容纳的接管登记/新 id 发布失败则退出启动分支，继续文件级监控/收集，不逐 tick 重试登记。按父类 `pumpPollMs` 运行唯一调度器，手动 tick 等待已在途步骤，定时器不重复排队；关闭准入后不再读取记录。正常 tick 跳过本进程提交在途及 created/submitted 条目；无 dsh 登记的 running 仍可结算，结算/回执后续 tick 才 collect。collected 与经校验的收集耗尽终态进入投递；通知已终结则经完整 notify 校验修复完成索引，不能直接跳过或仅凭 status 迁移。启动分支及投递边界详见 [重启恢复](../03_SPEC/Park_Resume_Design.md#9-服务重启恢复)。

结算先读 `exit_code`：完整且处于安全整数范围内的十进制整数决定 succeeded（0）或 failed（非零）；已有取消请求也不覆盖退出码。空白、部分数字、小数、不安全整数或不可读文件导致 failed、null exit_code 与明确诊断，原文件保留给后续 collect。仅 ENOENT 表示不存在；此时检查包装进程身份与状态，以时间戳数值比较而非 ISO 字面值比较。观察到消失、身份不同或 Z 状态后必须重读退出码；仍无才按 cancel_requested_at 判 cancelled，否则 failed 并给出 lost 诊断。无法确定的检查或损坏/不一致记录记录错误且不改持久状态、不结束登记，其他条目继续处理。

正常执行结算先原子写 `run-job.json` 的终态、finished_at、exit_code，再调用本地 `settle` 并等待 `done`；succeeded/cancelled/failed 分别映射到父类 completed/killed/failed。持久化失败不经此路径完成登记；完成回调失败保留回执，在后续正常 tick 重试，不改写既有终态、finished_at 或文件修改时间。回执完成前不收集；后续 collect 可以将终态投影为 `collected`。结算与 collector 本身均不迁移活动索引或发送消息；同一轮询循环的后续投递步骤拥有唤醒和通知终结后的索引迁移，不另挂完成事件订阅者。宿主 teardown 的登记级 detach 与此 durable 结算路径分开。

公开 `kill(id, caller, reason)` 保持同步返回 `requested | already-finished`，覆写本实例实际提交或启动 R3/R5 接管并关联的 SHUD 登记，不靠 `kind: shud` 字符串或扫描目录认领作业。先经父类公开 get 做访问与终结状态检查：未知、无权限、已完成或非托管登记保持父类语义；托管活作业在 D7 在途或关闭准入后明确拒绝，不写取消标记、不发信号。接管必须通过新鲜 current id、pid/start 与组所有权检查；registered 事件中、新 id 尚未持久化的重入 kill 以身份 MISMATCH 拒绝，不写意图、不发信号，发布后沿用同一公开 kill 路径。首次有效请求以同步原子写持久化 `cancel_requested_at`，随后在调用父类前镜像原始期限到本地 `requestedAt` 并设置一次性标记；适配后的 producer cancel 消费该标记，经本地 spawn 或已验证恢复的组能力发 SIGTERM。重复请求保留首次时间和期限，不重复发 SIGTERM；持久化失败不设镜像/标记、不发信号，父类抛错/返回 already-finished 清除未消费的临时标记，但保留已持久化意图及本地镜像。Web 固定理由、模型任意理由乃至 `"jobs service disposed"` 都不决定调用来源；无一次性标记的托管 cancel 走宿主 teardown。

父类公开视图可在异步 `settle`/`done` 完成前滞后于持久终态；kill 以非让出式转换内新鲜且已通过身份/路径校验的 RunJob 为准。若状态已为 `succeeded`、`failed`、`cancelled` 或 `collected`，同步返回 `already-finished`，不写元数据、不设取消标记、不检查进程组、不发信号，也不调用父类 kill。仍为 `running` 时即使已有数值 `exit_code` 文件也照常接受取消请求，后续结算仍保留自然退出证据的优先级。

宿主在线的取消结算由既有轮询 cadence 升级，不新增定时器：按 core `KILL_GRACE_PERIOD_MS = 10000` 从首次请求计时，时钟回退不加速，到期且受控组仍可 I/O 才发 SIGKILL，每次信号前复核所有权。包装进程先退出而抗 SIGTERM 后代仍活着时不能提前结算 durable 结果，必须继续跟踪该组至静止。静止后按严格退出文件 first-wins 结算：有效数值文件仍决定自然成功/失败，无文件且有最新取消意图才是 cancelled，非法/不可读文件仍是 failed；正常执行的持久化终态和本地回收先于 producer 完成。

宿主 teardown 在同步 cancel 回调内调用 `detach`：无取消意图时不发信号，以受控 detail 说明 SHUD 继续后台运行；有本地持久意图镜像时先经原所有权证明重发 SIGTERM，再以 kill-in-progress detail 结束登记。信号/检查失败记录受控阶段和错误码，`finally` 仍完成同一个 done 为 failed，不冒充进程已终止。此登记级路径不读写 RunJob/索引、不 collect/唤醒、不 SIGKILL、不等待进程或重置期限；已接受的启动 R8/正常异步工作（包括通知 flush、失败记账、标记与索引发布）仍由组合生命周期按 drain 规则排空后放锁。SHUD 登记无 owner，发起 Agent 释放不影响其继续运行、收集与投递，也不通过 `job/settled` / tool-jobs 重复唤醒；Darwin R7/Linux R8 原生验证及 #343 边界见 [重启恢复](../03_SPEC/Park_Resume_Design.md#9-服务重启恢复)。

取消写入、轮询终态、collect 状态投影及通知状态更新共用新鲜 RunJob 的同步校验/转换/原子发布边界：读取、身份/路径校验、字段转换与 `writeJsonSync` 之间不 await，保留本次转换不拥有的最新字段，不以旧快照覆盖取消意图或回退新终态；cancelled 与 lost 的选择也读取该边界内的新标记。提交期元数据仍由 D7 隔离；RunRecord 与收集重试记录保持原有异步发布、不可变结果及重试提交边界。

注册表公开后端 API `collectShud(id: RunId | JobRecordId): Promise<RunRecord>`，先查活动再查完成索引；已挂载的 `shud_collect` 仅接受两个持久 id 之一，按 core 品牌校验，拒绝未知键/错误根类型，并只委托一次该 API。调用会话 cwd 不参与查找，未索引的磁盘记录仍为未知 id。它与自动 collect 使用同一实现和逐条目队列；失败调用不阻塞后续请求。非终态与提交在途拒绝包含经校验的当前状态/nullable `dsh_job_id`，不创建结果或重试记录。D7 在请求接纳时捕获，仅排队读取身份校验后的错误快照，即使提交期间完成也不转为收集；已接纳读取受既有 drain-before-unlock 约束。普通终态请求等待已接受工作及未完成回执，再进入规范收集。只读后端 API `listRunJobsByTask(task_id: TaskId): Promise<RunJob[]>` 在索引遍历和文件读取前校验 core TaskId，快照自有活动与完成索引，逐条复用运行路径/身份校验并在异步读取后复核目录所有权，再经完整 core RunJob schema 校验；任一已索引记录失败（包括其它任务）即以该 run_id 与受控原因拒绝整个查询，不回显原始载荷。仅返回 task_id 匹配项，按 job_id 码点升序；completed 已发布而 active 尚未移除时，同一 run_id/job_id/run_dir 按 active 优先仅返回一次，不掩盖冲突身份。所有 schema 合法状态、M2 null 引用及提交在途记录均可查询，无匹配返回空数组，结果与持久状态脱离；不查 TaskCard/StackLock/DataProvenance 文件，不依赖会话 cwd、不扫描未索引记录，不触发轮询/收集/日志或任何文件、索引写入，也不进入逐条目队列。启动对账就绪前与关闭准入后拒绝；同一组合生命周期 effect 同步关闭查询准入，独立排空已接受的只读查询（成功或失败）后才释放 stateDir 所有权，查询失败不阻断清理。工具用法与实测边界见 [Repository Layout](Repository_Layout.md#已挂载的-shud_collect)。

收集先验证运行路径与身份，再校验终态完整字段。缓存的数值 exit_code 必须有相同的有效退出文件；缓存为 null 时，有效文件可恢复退出分类，仅文件真正缺失才按取消状态/标记判 cancelled，否则 lost。不可读、非法或不一致的退出证据明确失败，不降级为 lost；退出证据失败将 RunJob 置为 `failed`，包括原 succeeded/cancelled，保留 exit_code、取消标记、身份与时间等其它字段。其它收集失败保留终态；无法合法重写的损坏记录保留原字节。日志只记录路径，输出仅扫描 `output/<project>.out/` 的元数据，生成排序的 POSIX 相对路径及实际字节数，不读取日志/产物内容；初始输出目录真正不存在可为空清单，链接、特殊文件、不可读目录或扫描中消失均失败。RunRecord 保留引用、argv 与模型来源；新数值 wall_seconds 仅由匹配的原始提交实例启动身份及其成功终态观测授权，等于 `(Date.parse(finished_at) - Date.parse(started_at)) / 1000`。缺时间、缺失或不匹配的观测、恢复/接管均为 null；有效数值退出或本地受控取消达到既有静止条件可形成观测，丢失/非法退出及非本实例发布的终态不能授权数值。已知负区间仍先经原有校验拒绝，不以 null 隐藏。finished_at 是结算观测时间，不是退出时间；同实例完成/收集重试不推进端点。窗口可含起点时钟偏差、检测延迟、取消宽限，不是求解器运行时长、求解器时长上界或固定精度测量；数值健康四项与 peak_memory_mb 保持 null。

经 core schema 校验后原子发布 `run-record.json`，再原子投影 RunJob 为 `collected`。有效且身份匹配的已有 RunRecord 优先原样返回，字节与 mtime 不变；结果发布是提交边界，后续状态投影失败只重试投影，不重新扫描、改写结果或增加生成失败次数。生成失败写本地 `collect-error.json`（严格的 `attempts`、`last_error`、`at`）；诊断仅含受控阶段、字段路径或 errno，不持久化/记录原始异常载荷。损坏的重试记录保留且不重置，并阻止新的生成尝试。自动路径首次及时尝试，之后沿用 core 常量 `COLLECT_RETRY_INTERVAL_MS = 10000` 与 `MAX_COLLECT_ATTEMPTS = 3`，按持久时间间隔重试，时钟回退不加速；直接 collect 可越过间隔/次数上限，但不能绕过损坏记录重新生成结果。成功重试保留既有错误记录字节与 mtime。

工具直接返回规范 RunRecord JSON；普通失败向调用方保留本次 `collect-error.json` 的受控原因。若失败记账/状态发布也失败，聚合错误仍包含原生成原因及受控发布阶段/代码，不转发任意 cause 或历史 ledger 文本。非终态诊断只校验路由状态与当前登记 id；终态完整 schema 校验仍属于收集尝试并按既有规则记账，不提前变成未记账的请求错误。

唤醒由 `packages/dsh-shud-jobs/src/shud-poll.ts` 的同一逐条目队列负责：可选会话服务就绪后才恢复 owner，使用 `createUserMessage` 的 `source.kind: shud-jobs`，经 `followup` 与正向 `sessions.flush` 后发布 delivered，再完成索引迁移。缺服务保持 pending 且不消耗尝试；撤销注入 epoch 后不得用晚到结果追加或记账。暂时性失败间隔至少 10 秒、上限 3 次，最后一次与 unreachable 原子发布；失败记账落盘前先重试原记账，不重发传输。确认的追加/flush 回执与待发布失败记账均为进程内知识，普通注册表重载保留，实际进程崩溃丢失；前者区分 live Session 与完整运行身份，后者另校验 owner，不能继承其它运行的预算。崩溃窗口允许至少一次重放，不保证 exactly-once，不新增持久 outbox。收集耗尽原因须由 `shud-run-file.ts` 校验受控历史阶段/代码并归一化，不能直接转发任意 ledger 文本；有效同身份 RunRecord 优先，不可信证据保持 fail closed。完整顺序与验收边界见上述重启恢复说明和 `openspec/changes/archive/2026-10-27-m2-run-chain/design.md`，不要在 collector 或其它订阅者建立第二条投递路径。

启动 R3 完成原有身份提升后与 R5 共用接管路径：经瞬时全局控制器创建无 owner 的真实 `kind: shud` 登记，沿用 run_id 加可选 label 与原 stdout；先清空旧 current id，再不让出地发布新 `dsh_job_id`、追加 `dsh_job_ids` 并安装完成回执，不重新 spawn。对每个运行，每个实例只接管一次，后续新实例再追加一次。登记/新 id 发布失败时保留已清空的 current id 和旧历史，受控报告；已产生登记则 detach、等待父类输出泵/终态、移除登记，最后释放托管关联，不 abort 物理执行或删除运行文件/索引，随后继续文件级 poll/collect 而不重试登记。清空旧 id 的存储失败仍是错误，不伪报 null；登记清理失败保留未完成关联并受控报告。R8 保持文件级恢复取消，不创建接管登记；启动阶段保留 pending notify，R12 修复已验证 delivered/unreachable 的完成索引，初始化后的普通轮询接续 #313 投递。后端与公开会话服务 doubles 的验证不等同完整宿主/Web 跨重启恢复或 PI 验收；工具入口 #314–315 与真实 Web 重启脚本 #316 已交付，`pnpm run shud:restart` 已登记为本机阻断闸，PI 已于2026-10-27通过手工验收 #318，实际会话与 RunRecord 见 `docs/Migration_Plan_dsh.md`；工程验证不替代该验收。R7 孤儿组边界（#343）已由 PI 选择安全所有权与仅日志诊断，不增加持久区分；`wall_seconds`（#344）按 PI comments 6397950076/6405181313 采用原始实例可重算观测窗口，缺观测的新记录为 null，已提交历史数值不改写也不追认证实，见上述收集说明。`pnpm run shud:tiny` 仍是独立真实求解器 smoke，与提交共用 `packages/dsh-shud-jobs/src/shud-end.ts` 的 END 更新器；`SHUD_TINY_DAYS` 默认仍为 30 天，其结果不能替代注册表运行证据。

最终 R7 在退出证据重读后、无本实例保留的 R8 组控制且终态发布成功时，collect 前经专用 `shud-recovery` Cordis facade 向宿主 stderr 输出一次受控 WARN：run_id、记录的 pid/start 身份已不再存活或匹配、历史组静止性未验证、不向未拥有的组发信号、后代可能仍活着。该 sink 按显式名称和公开 metadata 的精确 WeakRef 身份隔离并随插件释放，不扩大既有错误或其它插件载荷的日志出口。R6、R3/R5、受控 R8、失败/延迟结算不误报，collect 重试或终态重载不重复；没有新字段/文件、信号能力或通知变化。RunRecord 的 cancelled/lost 不能证明后代已停止；终态发布后告警前崩溃、stderr 不可用或日志丢失会永久丢失这一区分。单次异步 fd 写入由本次回调承接失败，失败或短写仅丢失日志，不终止宿主或中断结算/收集，不重试、不回退、不转发原始错误载荷。运维须核实当前身份/组控制，禁止凭历史 pid/pgid 裸发信号；日志不是 Web 面板或新的唤醒事件，同宿主替换测试不是完整 Web 重启证明，#293/#318 的集中 PI 验收已于2026-10-27通过，证据独立记入 `docs/Migration_Plan_dsh.md`。
